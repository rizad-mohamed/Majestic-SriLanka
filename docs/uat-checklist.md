# User acceptance and launch checklist

Automated validation is recorded separately in the handover report. These boxes are for actual client review; none imply approval.

- [ ] Compare homepage at desktop scale with the supplied reference: header proportions, hero line breaks/fade and fortress placement.
- [ ] Inspect section sequence, vertical rhythm, editorial typography and forest/bronze palette.
- [ ] Confirm elephant collage, smaller landscape, transparent leaves, individual paper notes, circular stamp and branch.
- [ ] Review experience silhouette, tea-picker cutout and curved beach CTA.
- [ ] Approve generated photographic recreations and approximate elephant brand mark, or supply originals.
- [x] User confirmed seven primary routes: Home, Tours, Tailor-Made, Experiences, About Us, Plan Your Trip and Contact Us. Travel FAQ is within Contact Us.
- [ ] Confirm all copy, proposed tour outlines and durations; specify real inclusions, availability and pricing before accepting bookings.
- [ ] Replace or verify reference guest quotations; obtain permission before displaying real guest names/images.
- [ ] Supply verified email, WhatsApp number and social profile URLs. No invented links are used.
- [ ] Supply story film if a video is intended; current control opens a clearly described written story.
- [ ] Confirm production domain; approve privacy and booking terms. Current notices explain the development behavior.
- [ ] Exercise desktop and mobile menus, search, carousel, hero selectors, tour filters and itinerary dialogs.
- [ ] Create and download a travel brief. Confirm no false delivery message appears.
- [ ] Verify configured email and WhatsApp handoffs manually, including actual message delivery.
- [ ] Check all pages at 320, 390, 768, 1440 and wide desktop widths; use real touch devices as well as emulation.
- [ ] Check keyboard focus, Escape, dialog return focus, form errors and text enlargement.
- [ ] Perform screen-reader testing with NVDA/VoiceOver; automated axe results do not establish WCAG conformance alone.
- [ ] Review measured Lighthouse reports; measure actual field Core Web Vitals after real traffic exists.
- [ ] Check production caching/security headers on the chosen host, 404 behavior, robots, sitemap and canonical domain.
- [ ] Set `PUBLIC_ALLOW_INDEXING=true` only after public-launch content approval and rebuild.
- [ ] Download and open the complete asset ZIP; verify all individual assets and source PNGs are present.
- [ ] Confirm GitHub Actions passes for the final pushed commit, and verify rollback to a prior version.
- [ ] Client signs off the final website and business content.
